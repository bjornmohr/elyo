# Paket 04, Etappe 2 (A14) — Abnahme

Stand geprüft: `findings/04-infrastructure-hardening-s2`, Commit
`e43a741`.

## Befund und Änderung

Die fünf Runtime-Rollenpasswörter hatten zuvor Fallbackwerte in
`.env.example`, `docker-compose.yml` und
`infra/postgres/initdb/01-databases-and-roles.sh`.

`.env.example` bleibt lokale Setup-Vorlage. `docker-compose.yml` verlangt nun
jede Variable mit `${VAR:?…}`. Initdb verlangt jede Variable mit
`: "${VAR:?…}"`. Fehlende Werte stoppen Compose oder Initdb statt Dev-Passwort
zu wählen. `README.md` beschreibt erforderliche Variablen für bestehende
Klone.

## Abnahme

Ausgeführt:

```text
docker compose --env-file .env.example config --quiet
```

Ergebnis: erfolgreich; nur bestehende `APP_NAME`-Warnungen.

```text
bash -n infra/postgres/initdb/01-databases-and-roles.sh
```

Ergebnis: erfolgreich.

```text
docker compose --env-file /dev/null config
```

Ergebnis: erwarteter Abbruch:

```text
error while interpolating services.migrate.environment.DB_IDENTITY_PASSWORD: required variable ELYO_MIGRATOR_PASSWORD is missing a value: ELYO_MIGRATOR_PASSWORD must be set
```

Prüfung auf Passwort-Fallbacks in `docker-compose.yml` und
`infra/postgres/initdb/01-databases-and-roles.sh`: keine Treffer für
`:-` oder `:=` bei den fünf Runtime-Rollenpasswörtern.

## Volume-Reset

Nicht ausgeführt. Initdb läuft nur mit frischem PostgreSQL-Volume. Bestehende
Volumes behalten vorhandene Rollenpasswörter. Änderung dort erst wirksam nach:

```text
docker compose down -v
docker compose up -d postgres
```

Dieser Lauf führt diese Befehle nicht aus; Paket-Randbedingung verbietet
`docker compose down -v`.
